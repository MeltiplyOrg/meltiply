# Frontend capability inventory

This inventory covers all app routes and public product surfaces. A backend API
does not imply a creator-facing workflow. Billing APIs and payment integrations
are not shipped; the community resource policy is defined in
[`COMMUNITY_LIMITS`](../packages/domain/src/index.ts).

## Retained surfaces

| Surface                            | Available workflow                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `/sign-in`                         | Protected first-run creation of one installation owner; subsequent owner sign-in, verification resend, password recovery, and optional authenticator/backup-code challenges. Deployed sign-in requires verified email; API authorization checks live owner sessions.                                                                                                                                                                                                                                                                                         |
| `/posts`                           | Compose and save Posts, attach composer-owned uploads, choose Channels and Provider settings, manually schedule publication, inspect publishing outcomes, retry eligible failures, and delete Posts individually or in confirmed batches. Selection survives List/Grid/Calendar switches; the bottom pill shows the count, Deselect, and Delete. Bulk deletion uses each Post's owning Brand Profile, including the aggregate view, and leaves published platform copies untouched. The Scheduled filter shows manually chosen times, not a time-slot Queue. |
| `/channels`                        | A table directory shows provider-badged avatars, titles, copyable usernames/IDs, Brand Profile ownership, health tooltips, recovery, and settings. Checkboxes select individual or visible filtered channels; a bottom action pill provides Deselect and confirmed bulk Disconnect. Failed actions remain selected for retry. Filter accounts, administer Brand Profiles when authorized, and connect accounts. Facebook requires explicit Page selection before saving. Connection availability follows server readiness.                                   |
| Sidebar and mobile navigation      | Posts/Channels navigation, List/Grid/Calendar shortcuts, real Brand Profile scope selection, account identity and sign-out, sidebar collapse, and a shared jump palette opened from Search or Command/Control-K. Settings exposes Appearance, read-only Account, and existing password-reauthenticated Security. The top bar exposes Search and Settings on mobile. Workspace identity is read-only; profile selection is not Workspace switching.                                                                                                           |
| `/`, unknown and retired app paths | Redirect to `/posts`, then through authentication when required. No legacy route aliases or preview pages.                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Public landing page                | Publishing, scheduling, Channel organization, and composer attachments. The clearly labeled interactive sample illustrates retained workflows with local sample content, not authenticated Workspace data; it cannot publish or persist real Posts.                                                                                                                                                                                                                                                                                                          |
| Public docs                        | Setup, Channels, Brand Profiles, composer attachments, publishing, preferences, troubleshooting, and legal guidance. Capability-status pages describe unavailable workflows instead of directing users to retired app routes.                                                                                                                                                                                                                                                                                                                                |

The publishing workspace uses immediate navigation and reduced-motion presentation.
Shared primitives retain focus and dismissal ownership; outgoing selection
controls become inert immediately.

## Removed or intentionally absent

| Capability                                   | Cleanup / absence                                                                                                                                                                                              | Restoration prerequisite and tracking                                                                                                                                                                                     |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Workspace switching                          | No sidebar switcher or Workspace selection workflow. Workspace name and role remain read-only.                                                                                                                 | Authorized membership selection, persisted choice, cache re-scoping, safe fallback, and accessible desktop/mobile interactions.                                                                                           |
| Time-slot Queues                             | Remove the Queues shortcut to the Scheduled filter and claims of reusable Queue scheduling. Manual Schedule and Publish Now remain available; `Queued` is a Distribution delivery state, not Queue membership. | Named Queues with recurring weekday/time slots and a timezone, composer Queue selection, automatic collision-safe slot allocation, visible assigned times, and verified publication through the existing delivery path.   |
| Post engagement metrics                      | Remove permanent empty metrics from grid, list, and calendar day detail, and the null-producing frontend helper/type. Remove analytics claims from Posts and Channel feature labels.                           | A real Post-to-Distribution metrics data path, defined aggregation and freshness semantics, loading/error/empty states, and consumer-visible regression coverage. Backend analytics capabilities/contracts remain intact. |
| Analytics and Inbox routes                   | No dashboard, comment reader, or reply action is advertised; their unused frontend clients have been removed. Backend APIs remain.                                                                             | Complete creator-facing flows with scope isolation, meaningful loading/error/empty states, and real-surface verification.                                                                                                 |
| AI Studio and Plugs                          | No demo assistants, recommendations, or automation controls.                                                                                                                                                   | Separately approved end-to-end workflows with established backend capabilities.                                                                                                                                           |
| Administration and Billing routes            | Settings is a focused Appearance/Account/Security dialog, not an administration route. No checkout, portal, billing API, notification configuration, or payment integration is advertised.                     | Additional settings require working, authorized administration; billing needs separately approved end-to-end product support.                                                                                             |
| Standalone media library                     | No library or asset-browser route. Uploads belong to a Post composition.                                                                                                                                       | Separate product approval and a complete ownership/lifecycle workflow; do not advertise a library on the strength of upload infrastructure.                                                                               |
| Team administration and collaboration claims | No invitation, membership management, approval, or collaboration entry point is retained.                                                                                                                      | Separately approved, authorized membership/collaboration UI and end-to-end coverage. Workspace roles alone do not satisfy this requirement.                                                                               |
| Brand Profile restoration                    | No restore control; backend soft-delete/restore operations remain.                                                                                                                                             | An authorized deleted-profile listing and restore interaction, with channel reauthorization and cancelled-Post semantics.                                                                                                 |

Removed app capabilities are not retained as previews. Landing sample content
illustrates supported workflows rather than restoring unavailable surfaces.
