# Frontend layout contract

This document owns layout and scroll boundaries for the current Gr8r-adapted interface. Use [shared UI ownership](frontend-ui.md) for implementation seams and [product conventions](../PRODUCT.md#modular-consistent-surfaces) for supported behavior. Exact shared values come from [`tokens.css`](../frontend/shared/tokens.css), not a parallel page theme.

## Alignment and scroll contract

Routes share one horizontal gutter: 16px on phones and 24px from the small breakpoint. Collection headers and Settings use the same 20px phone / 24px small-breakpoint top padding, so a route's heading, toolbar, and content begin on one edge; documented maximum widths apply only to prose, forms, and the directory composition, never as a second page inset. Settings adds its 220px section rail from 768px, which explains its additional x offset. Fine-pointer table rows keep the 36px collection density, while coarse-pointer selection targets grow to 44px inside their cell. The shell never scrolls: each route owns its explicit scroll regions, with Administration's height-locked tab lists as the documented exception. Horizontal scrolling belongs only to the table or calendar canvas, or to a deliberately scrollable segmented track. Settings centers its active section in the rail and returns the content pane to the top when the section changes.

## Workspace shell

`NavigationShell` owns the viewport frame, persistent header, desktop rail, `MobileNavigationSidebar` layer, skip link, and route working column. Routes own their headings, toolbars, content gutters, and scroll regions; the shell does not add a second padded card.

| Region            | Current geometry and behavior                                                                                                                                                                                                                                                                                                                                                                                                       |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Desktop rail      | Visible from 1024px; 252px expanded or 52px collapsed. Destinations scroll independently of the account/footer controls.                                                                                                                                                                                                                                                                                                            |
| Header            | 52px below 640px; 46px from 640px. Contains navigation access, workspace/profile context, page title, and jump search.                                                                                                                                                                                                                                                                                                              |
| Mobile navigation | Below 1024px, the header opens `MobileNavigationSidebar`: a full-height, at-most-320px layer over the workspace that slides in from the left behind a fading scrim and contains the same `SidebarNav` as desktop, without its collapse control. Escape, the scrim, a destination, or the desktop breakpoint closes it; the workspace is inert while it is open. Help, account settings, theme choices, and sign-out stay available. |
| Working column    | `min-w-0` and `min-h-0` preserve bounded scrolling. No document-level horizontal overflow.                                                                                                                                                                                                                                                                                                                                          |
| Route gutters     | Normally 16px on phones and 24px from the small breakpoint. A collection owns its own edge treatment.                                                                                                                                                                                                                                                                                                                               |

Posts is one destination. Its view switcher belongs in the page toolbar, in **Table → Calendar → Grid** order. Brand Profiles remain collection scope and a Channels tab; jump search belongs in the header.

Queues is a calendar-first destination with one owning Brand Profile, defaulting to the first available profile when the workspace has no valid single selection. From the large breakpoint, a neutral selectable plan rail reuses `w-80`; the calendar takes the remaining shrinkable width. Phones replace the rail with a compact Queue selector and actions menu, keep profile/refresh on one row, and omit the desktop explanation so the calendar retains useful height. Month reuses the Posts actual-date grid, fits all seven columns on phones, and interleaves chronological slots and off-plan Posts with filled/unfilled counts that open the containing Week. Week uses the shared horizontally swipeable hourly canvas with sticky dates and time axis; its initial position reveals today rather than always starting at Monday. Filled slots render the real Post chip, unfilled occurrences render a dashed open slot that mutes once elapsed, and both are bounded by the visible window and the plan. Today and Month/Week controls stay outside the scroll region. The Queue's timezone governs assignment placement and the live red current-time rule, which is drawn only inside today's column when that column is visible; the clock refreshes every 30 seconds and on tab return without moving the user's scroll. Month↔Week changes animate through native View Transitions: only the seven shared date labels morph, the rest of the calendar crossfades, the toolbar stays still, and reduced motion commits immediately. Hour geometry comes from the shared calendar tokens. The visible window is fully paged before it is reported complete; configuration and reservation/destructive actions retain canonical centered dialogs, while inspecting an assigned Post opens the shared Post drawer immediately.

On short phone viewports the Queue content area can scroll vertically rather than shrinking the calendar below its shared `min-h-120` floor; desktop retains the height-locked calendar/rail split. Dialogs remain outside that scrolling wrapper.

The shell and drawer frames use the shared safe-area tokens for viewport cutouts and home indicators. Coarse-pointer buttons, select triggers, and menu rows have 44px minimum heights; text fields retain 16px text to avoid phone focus zoom. Fine-pointer controls keep desktop density.

## Collection surfaces

### Posts

`WorkspaceSurface` composes the page heading/actions, toolbar, active filters, and selected collection view on the shared surface background. On phones the heading and primary action share one row with the description beneath, and the collection toolbar uses two compact rows: search with the view selector, then filter, sort, group, and column controls. Group and column controls keep their accessible names while showing icons only; the collection therefore begins within roughly the first 220px below the workspace header instead of after four stacked filter rows.

- **Table** is the default. The shared spreadsheet table has a sticky header, selection column, title, optional metadata, and counted collapsible groups. Rows paint the shared table hover fill, and the header row stays pinned while the table scrolls; a group's toggle turns its chevron while its rows collapse in place with a height transition, staying mounted so expanding and collapsing animate alike. Status, Brand Profile, or no grouping changes presentation without changing identity or selection. Rows reach the working edges and inset the leading cell. There is no trailing actions column. On coarse pointers the selection cell fills its 48px column at 44px tall for rows, the select-all header, and the loading skeleton, so touch targets match the shared control height; fine pointers keep the 36px row and 16px checkbox.
- **Calendar** is a flush canvas, not a nested card. Its toolbar contains Today, previous/next, the period heading, and Month/Week controls. Month is Monday-first with 35 or 42 local dates, 112px minimum rows, three Post chips per day, and overflow/day-list access. Week uses seven date columns. The canvas may scroll horizontally; its surrounding controls wrap.
- **Grid** uses `PostCard`, real attachments, and the selected column count. A bottom analytics row shows icon-led views, likes, comments, and shares in four non-wrapping slots, with compact localized counts and accessible exact values. Draft, unpublished, and unmeasured counters show a dash; measured zeros stay zero. The loading card reserves the same footer. The grid viewport owns its gutters. Cards reflow rather than causing document overflow.

Table, Grid, and Calendar day lists share real Post identity, selection, and supported actions. A partial selection leaves select-all visually unchecked. The shared bottom pill reports the actual selected count and opens the existing destructive confirmation.

Post collection reads request at most 60 records at a time. Grid renders at most 60 matching cards, with Previous page, a page number, and Next page beneath the cards; page changes return its viewport to the top. Table keeps loaded rows and appends the next batch only through its bottom Load more button, which remains reachable outside the horizontally wide table. Presentation filters operate on the loaded collection and reset Grid to its first page; navigation remains reachable when no loaded rows match. Calendar retains its separately bounded month event query.

All three views load inside the same frame they resolve into: while a query is pending, the page header reports the loading state instead of a zero count, the toolbar and table head stay mounted, the Table renders its real column slots as placeholder rows, the Grid renders placeholder cards with the `PostCard` anatomy, and the Calendar keeps its real period controls and dates with placeholder chips. The shell's own frame covers the session and route-chunk waits as one shape (`WorkspaceLoadingSkeleton`, painted from `index.html` before the module graph arrives), and the header's workspace name holds a placeholder bar until the Brand Profile resolves. Loading therefore never changes the page's height, columns, or scrollbars.

### Channels

Channels uses the Members-style directory composition, not a copy of Posts grouping: a centered 1200px maximum, heading/actions, underlined Accounts/Brand Profiles tabs, account search, connection-status segments, field-row filters, and an inset directory table.

The directory header row stays pinned to the top of the accounts viewport, and that viewport owns both scroll axes, so the wide table scrolls sideways without capturing the sticky header in an inner scroller. Accounts show identity, platform, owning profile, a single accessible health icon, and channel settings. The Brand Profiles tab shows real profile cards and connection counts. Both tabs use the same background and canonical controls as Posts. Table horizontal overflow stays inside the directory viewport.

Account identity keeps the saved name above a single compact username/ID line.
Adding a username does not add another line or increase row height. Both metadata
values truncate within the Channel column and are directly clickable for copying;
there are no separate copy-icon columns or vertically stacked copy controls.

The post-OAuth `/channels/connect` page pairs the shared Meltiply mark and provider
mark directly on the canvas, without logo tiles, with a link glyph between them.
Brand Profile assignment uses a bounded native-scrolling radio list with a focus
gutter. Only connectable profiles appear, preserving workspace order. An already
connected account can reconnect only to its current owning profile; empty slots
on other profiles cannot accept it until it is disconnected. If none can accept
the selected Channel, an explanatory empty state replaces the choices. Page actions
remain outside the list's scroll boundary.
Account selection keeps the neutral row border and uses the trailing checkmark.
Account and Brand Profile rows show a focus ring only for keyboard navigation,
not pointer clicks; Profile selection uses its fill and trailing checkmark.

### Analytics

`/analytics` is a read-only operational page inside the shared `WorkspaceSurface`. Its toolbar uses the same compact collection filter builder as Posts: one Filter disclosure holds Brand Profile, range preset, platform, connected account, and content format, active values become removable chips, and Refresh stays beside it. The toolbar wraps on narrow screens instead of scrolling horizontally. It never switches the dashboard into a single-metric mode. The body scrolls independently and fills the available width: a KPI grid of two, three, or five columns, then one full-width performance-trend card whose four lines (views, likes, comments, shares) share one indexed scale and restore absolute values on hover. A responsive two-column grid follows with the stacked engagement-by-platform chart (likes, comments, and shares; views and posts in its tooltip), posts over time, follower evolution, and the content-format list that shows posts, per-post averages, and totals together. The 7x24 best-time heatmap and the platform breakdown table span the full width, and the top-Posts table keeps all four metric columns visible with header re-ranking. Posting-frequency and engagement-accumulation diagnostics are not separate cards; the dashboard endpoint still returns their data. Chart-local selectors use the shared sliding segmented control. Saves/clicks columns appear only when a provider reports them; otherwise a footnote names them as untracked.

Brand Profile is available inside the same Filter builder and scopes every analytics query through the workspace selection. Changing it clears the account filter; Clear all restores All Brand Profiles and the default range in one update. The filters remain available for profiles without connected channels. The platform breakdown uses native content-based column sizing to fill its card with only visible metrics, with horizontal scrolling confined to the table on narrow screens.

The standard table collapses to stacked Post rows below `lg`, with metric labels beside each value. The chart keeps its documented `role="img"` summary and a visually hidden equivalent table. Loading skeletons preserve the KPI, chart, and table heights, and refreshing keeps prior data mounted.

Analytics Day/Week/Month changes morph the marks in place. Bars keep the chart mounted and FLIP each rendered stack from the previous view's geometry, so days merge into weeks and split back without a React render per frame; the published value axis describes the destination from the first frame. The line chart animates each rendered path from the previous curve sampled at the new endpoints, so the curve reshapes into its new bends instead of redrawing. An interrupted change starts from what is on screen. Heatmap metric changes interpolate cell intensity without replacing the grid or scroll position. Native reduced motion renders both updates immediately.

## Settings

All sections share one layout; Security does not get a separate width rule.

- Navigation and content use the same surface background.
- Below 768px, section navigation is a horizontally scrollable row; from 768px it is a 220px rail.
- Settings content uses the collection pages' **20px phone / 24px small-breakpoint** top padding and the **16/24px** horizontal gutter, so its heading aligns with Posts and Channels at desktop; the 220px section rail explains its additional x offset.
- The horizontal section rail centers its `aria-current="page"` section with its own `scrollLeft` on mount, on section change (including reload and history navigation), on language change, when late label growth, a resolved section roster, or a resize changes the rail geometry; it clamps to the scrollable range and leaves a non-scrolling desktop rail untouched. A section change also returns the content pane to the top, while a language change keeps the reader's position.
- Appearance, Language, Account, and Security all use one left-aligned **672px maximum** content column with full available width below that limit.
- Administration uses the directory composition: a centered **1200px** ceiling, a content-width tab strip, and shared **spreadsheet grid tables** for Members and pending invitations. Workspace is a 672px settings form with its seat counts as a compact label/value summary rather than a table. The Administration route is height-locked — only each list scrolls. The Installation Owner is marked by a crown tooltip; their lifecycle control is a toggle and row actions collapse into a three-dot menu. Its Audit tab owns a bounded scroll viewport — a pinned header over 100-entry pages with a paging footer — while the toolbar's search, action, and target filters have fixed widths, Refresh re-reads the current page, and every filter applies server-side across the whole trail.
- Light, Dark, and System cards are **192px**, wrap, and do not stretch to fill a wide screen.
- The content pane owns vertical scrolling. Security forms and authenticator controls are inline; focused confirmation/enrollment steps retain their real security requirements.
- Busy security actions and pending authenticator enrollment/recovery codes block section, route, and history departures until completed or explicitly cancelled; reloading/leaving the document warns before unloading.

## Dialogs and floating controls

`CenterDialog` owns focused forms and search; `CenterAlertDialog` owns destructive confirmations. Both share one centered `dialogChrome` surface and focus treatment while keeping distinct dismissal semantics: the ordinary dialog dismisses from outside or Escape and exposes a localized Close, and the destructive confirmation blocks outside dismissal, focuses Cancel, and still cancels on Escape. `SideDialog` owns large Post inspection: a 620px right-edge drawer, a compact 46px toolbar, and the full-viewport phone layout. It is a non-modal companion — the workspace stays clickable so another Post is inspected in place — and it never dims or blocks the surface behind it. Composition uses the same drawer: **Shared Content**, media, and selected Channels' customization/settings sections form a continuous scrollable editor. Wide panels use a 340px destinations/publishing column, with the remaining width assigned to the editor and independent overflow in each column; the draft's save state and single primary action remain pinned below. Shrinkable ancestors bound the columns, and sections do not shrink into one another. The split is a container query on the panel, so narrow panels stack in one reading order inside the drawer's native scrolling body instead of squeezing two columns.

Dialog bodies own native scrolling and keep `data-lenis-prevent` where the document's smooth-scroll controller must not intercept them. Primitives own Escape, scroll lock, and opener restoration; the side inspector deliberately leaves focus untrapped so the workspace stays reachable, while the phone navigation sidebar and the centered dialogs keep containment.

Centered forms and confirmations have 16px viewport gutters and a maximum height of `100dvh - 32px`; their canonical primitives own native scrolling rather than each caller setting a `vh` ceiling. Jump search retains a shrinkable results viewport between its input and keyboard-help row. The mobile navigation sidebar spans the full viewport height on the left edge.

The Brand Profile dialog's 51-color palette reflows by available content width with a single rendered set of swatches: the 9/8 honeycomb with capped 42×48px cells on wide dialogs, a six-column grid on medium dialogs, then progressively fewer columns (five to one) as the dialog narrows. At 320px it uses four 42×48px columns. Narrow layouts scroll vertically inside the dialog, so every swatch stays reachable and the name and description fields remain inside the surface. Delete, Cancel, the primary action, and any mutation failure share one sticky opaque block at the dialog's scrollport bottom, so they are reachable before the palette is scrolled; the block reserves its own flow space, keeping the final swatch visible at maximum scroll, and publishes its height as the dialog's scroll padding so keyboard focus never rests underneath it.

`BulkSelectionBar` is portalled outside clipped collection viewports. Its inverse-ink pill stays 24px above the safe-area edge and within the available viewport width.

## State, motion, and verification

Keep control identity, unsaved content, selection, and keyboard focus stable as labels or state change. Hidden columns retain underlying data; filters operate only on loaded, authorized records. Scope changes clear selection according to the owning feature's contract.

Drawer focus entry and opener restoration use `preventScroll`; neither may move the underlying collection. A non-modal inspection can remain open while the list scrolls, so dismissal preserves the current viewport rather than rewinding to where inspection began.
Inspecting a background Post hides rather than unmounts the live composer; returning preserves its local inputs and upload tasks. Only explicit composition dismissal or a deliberate identity/scope change releases it. URL-backed composer intent opens and closes on same-route navigation as well as reload.

At the composer's wide split, independently scrolling columns reserve a 4px focus gutter so textarea, input, select, and button rings remain visible at every edge. The editor compensates its gutter with margins to retain the shared content alignment; phone layouts keep the drawer's existing outer padding. Do not remove the clipping boundary or shrink a shared focus ring to work around a column's missing space.

There is one implemented animation path, with no application motion mode or mode-specific guards. Preserve existing animation recipes when cleaning up; extend their canonical owners when animation work is requested.

Native `prefers-reduced-motion` remains independent: CSS overrides shorten declarative motion, and the shared WAAPI owner skips spatial effects. Interrupted toolbar exits cancel their own animation and stale completion callbacks before the next intent settles.

Smooth scrolling has one owner, `frontend/app/src/components/layout/smooth-scroll.tsx`. The document controller (`SmoothScroll`) smooths the window and deliberately stays out of every region marked `data-lenis-prevent`, so it can never swallow a nested wheel gesture. Each list viewport that owns its scrolling — the Posts table, Grid, Calendar, and both Channels directories — attaches the callback ref returned by `useSmoothScrollContainer`. Its controller follows the mounted element, destroys itself on detachment or replacement, and rebuilds against the current first child when content is replaced. It re-measures when descendants change and snaps its scroll position to whole pixels so a `position: sticky` header cannot flicker along its top edge while the container animates through fractional offsets.

Verify the actual desktop, phone, and reported user viewport. Cover both palettes, long content, loading, empty/error states, keyboard traversal, nested scrolling, and available actions. Every bounded scroller needs shrinkable flex/grid ancestors; only the intended table or calendar canvas may overflow horizontally.
