# UI translations

The frontend app ships English and Spanish. English source copy is the
translation key: `t("Dashboard")` stays `t("Dashboard")`, and a missing Spanish
value falls back to the English string. Catalogs live as data under
[`frontend/app/src/locales`](../frontend/app/src/locales):

```
locales/
  glossary.json        shared product vocabulary and intentional identicals
  en/ui.json           every English UI string mapped to itself
  en/status.json       status identifiers mapped to English labels
  es/ui.json           Spanish UI strings
  es/status.json       Spanish status labels
```

`translate()` and `tStatus()` read the `es` files directly, so the runtime and
the translation pipeline share one source of truth. Dev-only pseudo-localization
still applies after lookup.

## Adding or changing English copy

1. Call `t("New English string")` as usual.
2. The catalog test fails until `en/ui.json` contains the literal. Add the key
   with the English string as its value (status labels go in `en/status.json`).
3. Draft Spanish offline:

   ```bash
   bun run i18n:generate --target es --dry-run   # list the strings that would be sent
   bun run i18n:generate --target es
   ```

4. Review the `es/ui.json` or `es/status.json` diff. Generation writes nothing
   until every namespace succeeds, and any dropped or renamed placeholder aborts
   the run with the committed files byte-identical.
5. Run `bun run i18n:check` (or the app check, which includes it).

Only keys missing from the target are sent. The committed target file is the
cache, so unchanged strings cost nothing; an edited English string is a new key
and is translated once. Generation never runs in CI.

## Commands

| Command                                             | Purpose                                                                        |
| --------------------------------------------------- | ------------------------------------------------------------------------------ |
| `bun run i18n:check`                                | Deterministic, model-free catalog gate. Used by the frontend app check and CI. |
| `bun run i18n:generate --target es --dry-run`       | Show the pending keys without calling the provider or writing files.           |
| `bun run i18n:generate --target es`                 | Draft missing Spanish values and write the locale files.                       |
| `bun run i18n:generate --target es --force`         | Retranslate every existing value. Use only for a reviewed terminology change.  |
| `bun run i18n:generate --target es --model @cf/...` | Override the Workers AI model for this run.                                    |
| `bun run i18n:lock -- --keys 'legal.*'`             | Lock reviewed translations. Commit `.shipi18n/locks.json`.                     |

`i18n:check` runs Shipi18n with the explicit `brace` placeholder grammar,
`--fail-on error`, full coverage, and the structural rules the product needs
(untranslated values, invented placeholders, missing or collapsed plural forms)
escalated to errors. Its ignore-key list comes from `glossary.json`, so
intentionally identical values (Platform names, identifiers, examples) do not
false-positive. The check makes no network request and needs no credential.

## Environment

Get both values from the Cloudflare dashboard:

1. Open **Workers AI** → **Use REST API**.
2. Select **Create a Workers AI API Token**, review the prefilled permissions
   (`Workers AI - Read` and `Workers AI - Edit`, account-scoped), create it, and
   copy the token once.
3. Copy the **Account ID** from the same page. `bunx wrangler whoami` also prints
   it.

The token is scoped to Workers AI and cannot deploy Workers or other
infrastructure. Put both values in the ignored root `.env`, never in source or
logs. Generation reads `process.env`; if direnv is not loading `.env` for you,
export it first:

```bash
set -a; . ./.env; set +a
```

Generation reads [`.env.example`](../.env.example) values from the environment:

| Variable                | Default                      | Purpose                                                          |
| ----------------------- | ---------------------------- | ---------------------------------------------------------------- |
| `WORKERS_AI_ACCOUNT_ID` | required                     | Cloudflare account identifier.                                   |
| `WORKERS_AI_API_TOKEN`  | required                     | Workers AI-scoped token (Read + Edit). Never commit or log it.   |
| `I18N_MODEL`            | `@cf/qwen/qwen3-30b-a3b-fp8` | Primary model.                                                   |
| `I18N_FALLBACK_MODEL`   | `@cf/google/gemma-3-12b-it`  | Used when the primary is unavailable or returns malformed JSON.  |
| `I18N_SEED`             | `20261019`                   | Fixed sampling seed; override to reproduce a batch or reroll it. |
| `I18N_TIMEOUT_MS`       | `120000`                     | Per-request timeout.                                             |

Generation uses `temperature: 0`, a bounded `max_tokens`, bounded exponential
backoff for rate limits, timeouts, and 5xx responses, and fails immediately on
authentication, permission, or quota errors. Seeding is best effort: changing
the model, prompt, glossary, or provider can change output even with the same
seed. The committed locale file plus the model-free check is what makes CI
deterministic.

## Glossary, locks, and review

[`locales/glossary.json`](../frontend/app/src/locales/glossary.json) holds:

- `style`: per-language tone guidance (informal `tú`, neutral Spanish).
- `keepVerbatim`: product names, Platform names, identifiers, and examples that
  must survive verbatim. These also become the check's ignore keys and the
  catalog test's allowlist.
- `preferredTranslations`: the product's domain vocabulary (Brand Profile,
  Post, Channel, Workspace) used verbatim in the generation prompt.
- `intentionallyIdentical`: additional strings that stay identical (shortcuts
  and single-letter labels).

Review the generated diff before committing. After review, lock the approved
translations with `bun run i18n:lock`; `.shipi18n/locks.json` stores hashes, not
strings, and lets the check warn when a later edit replaces reviewed wording.
Normal generation only fills missing keys; `--force` is the only path that
replaces existing values and always needs a reviewed diff.

## Adding a language

1. Add the locale code to `supportedLanguages` in
   [`i18n.tsx`](../frontend/app/src/lib/i18n.tsx) and wire the selector.
2. Create `locales/<code>/ui.json` and `locales/<code>/status.json` (empty
   objects are fine) and add style guidance for the code to the glossary.
3. Run `bun run i18n:generate --target <code>`, review, and commit.
4. `i18n:check` discovers the new locale directory automatically.
