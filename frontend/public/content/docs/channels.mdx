Open **Channels** to manage the accounts used for publishing. The page has two tabs: **Accounts** for connected accounts and **Brand Profiles** for their owning profiles. Both use the same warm palette and shared controls as Posts.

## Connect an account

Every connection belongs to one Brand Profile. If none exists, workspace admins can select **Create Brand Profile** in the header; members must ask an admin. **Add account** becomes available once a profile exists.

1. Select **Add account**.
2. Find the platform in the Social Channels list, using its search field if needed.
3. Select **Connect**, sign in on the platform, and approve the requested access.
4. On the connection page, choose an authorized account and the Brand Profile that should own it. Only profiles that can accept that account appear.
5. Select **Connect Channel**. The account appears in Channels only after confirmation succeeds.

Each Brand Profile connects at most one Channel per provider. To replace that Channel with a different account, disconnect the current one first or choose another eligible Brand Profile. Reconnecting the same account remains available. A direct link to `/channels?tab=add` opens the platform connection dialog.

An already-connected account can reconnect only to its current Brand Profile.
An empty Platform slot on another profile does not transfer ownership; disconnect
the account first if it should move.

On phones, each platform's saved accounts and connection action appear below its identity instead of competing for the same row. Scroll the connection dialog to reach every platform; it stays within the available screen height, including landscape orientation.

Connection availability comes from the server and the platform's requirements. An unavailable provider is not a working connection action. Existing accounts remain identifiable by their saved name or provider account ID.

### Facebook Page selection

Facebook authorization returns all eligible Pages from direct management and,
with `business_management` consent, Business Manager assignments. Each discovery
list is paginated and duplicate Page IDs appear only once. Existing grants must
reconnect to add Business Manager discovery permission.

Choose the Page and its owning Brand Profile on the connection page, then select
**Connect Channel**. Even a single eligible Page requires confirmation; cancelling
does not add a Channel. The selection expires after ten minutes. If it expires,
start Connect again.

Eligible Pages require content-creation access and publishing permissions.
Token revocation or changed platform permissions can invalidate a working
connection. Community deployments do not impose a Channel-count quota; see
[Resource usage](/docs/resource-limits) for infrastructure responsibility.

### Supported providers

The connection flow currently includes TikTok, YouTube, Instagram, Facebook Pages, and Threads. Supported publishing formats and account requirements are shown by the real platform capabilities and composer validation; a listed provider does not imply every feature of its native app. Instagram, Threads, Facebook Pages, TikTok, and YouTube also report stored performance metrics to the [Analytics](/docs/analytics) page when their analytics scopes are granted. Reconnect an existing channel after an analytics scope is added so the Provider issues a token that can read it.

| Platform  | What one authorization makes available                                                                                                                                         |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Facebook  | Eligible managed Pages, including consented Business Manager assignments. Choose the Page in Meltiply.                                                                         |
| Instagram | The Business or Creator account used for Instagram Login. Sign in again to connect a different account; Facebook Page access does not grant access to every Instagram account. |
| Threads   | The Threads profile that authorized the app. Connect another profile through another authorization.                                                                            |
| TikTok    | The TikTok account that authorized the app, with basic-profile and publishing access.                                                                                          |
| YouTube   | The personal or Brand Account channel authorized through Google. Authorize each channel separately; Meltiply refuses a grant that cannot identify one upload destination.      |

All platforms still require explicit **Connect Channel** confirmation and an eligible Brand Profile. Cancelling a pending assignment does not disconnect an existing Channel. Reconnecting the same account updates its credentials without adding another Channel.

An installation must configure its own provider credentials, exact callback URL, and required permissions. Meta access approval, Google consent-screen/test-user access, and TikTok approval remain provider-side requirements. In particular, TikTok restricts unaudited Direct Post clients and does not accept an internal-only uploader as an audit use case; see its [Content Sharing Guidelines](https://developers.tiktok.com/doc/content-sharing-guidelines). Community resource freedom does not override these platform policies.

## Use the Accounts directory

Each account row shows:

| Column        | What it contains                                                                                                            |
| ------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Account       | Avatar or initials, saved name, and one compact line of available username/provider ID. Click either value to copy it.      |
| Platform      | The provider's mark and name.                                                                                               |
| Brand Profile | The owning profile, or Unknown profile when it no longer resolves.                                                          |
| Connection    | One health icon. Its accessible name and tooltip expose the status; connections needing attention provide recovery actions. |
| Settings      | The account's settings action, including permissions, publishing support, owning profile, and disconnect controls.          |

Click a username or provider ID directly to copy its raw value. A toast confirms
the copy; if clipboard access fails, it explains how to copy manually. These text
actions also work with the keyboard. Accounts retain the same compact layout
whether or not a username is available.

### Search and filters

Use account search to match account, platform, or profile names. The **Connection status** segments narrow the current health state.

Open **Filter** to add **Platform** or **Brand Profile** rows. Choose a field with its Add filter chip, then select a value. Adding an empty row does not change results. Supported rows combine with **and**.

- A row's trash control removes that filter.
- **Clear all** resets the builder.
- Active-value chips remove individual applied filters.
- **Clear filters** recovers a filtered-empty directory.

Selecting a Brand Profile scopes the shared Posts/Channels view. **All Brand Profiles** returns to aggregate review. Profiles are not sidebar sections; the top-bar jump search can also find a loaded profile.

### Select accounts

Select individual rows or use the header checkbox for all visible filtered accounts. The header is checked only when the entire visible set is selected; a partial selection leaves it visually unchecked.

The floating selection pill reports the actual count and offers **Disconnect** and the icon-only **Deselect** control. Disconnect confirms a fixed batch: successful accounts leave the selection, failed accounts remain selected for retry. Filtering does not discard hidden selections; changing Workspace or Brand Profile clears selection.

## Recover a connection

| Status             | Meaning                                   |
| ------------------ | ----------------------------------------- |
| Connected          | Authorization is working.                 |
| Expiring           | Authorization is nearing expiry.          |
| Expired            | Authorization must be renewed.            |
| Reconnect required | Authorize access again before publishing. |
| Revoked            | Access was withdrawn.                     |

For a connection needing attention:

1. Select its warning health icon and review the reason.
2. Choose **Re-authenticate** and approve access on the platform.
3. For Facebook, choose the same Page and confirm **Connect Page**.
4. Review the saved status when you return.

Re-authentication keeps the account's owning Brand Profile. An unrecognized connection-result code is not displayed as a success.

## Disconnect accounts

Open an account's **Channel settings**, choose **Disconnect**, and confirm. This works in aggregate and profile-filtered views; selected batches use the same confirmation principle.

Disconnecting removes the connection and stops scheduled/queued publishing for that account. It does not remove already-published platform copies. To revoke provider-side access, use that platform's app settings. To connect again later, start **Add account**.

## Manage Brand Profiles

The **Brand Profiles** tab shows actual profiles and their connected-account counts. These counts describe the workspace's connections, not just the current account filters. **View channels** applies the profile and returns to Accounts.

Admins can create a profile from the header or edit one from its card in the **Brand Profiles** tab. Creating a profile selects it and opens account connection. Deletion is in the profile editor and requires confirmation; read its consequences before proceeding.

See [Workspaces & Brand Profiles](/docs/workspaces) for ownership, permissions, and deletion behavior.
