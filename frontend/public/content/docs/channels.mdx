Open **Channels** to manage the accounts used for publishing. The page has two tabs: **Accounts** for connected accounts and **Brand Profiles** for their owning profiles. Both use the same warm palette and shared controls as Posts.

## Connect an account

Every connection belongs to one Brand Profile. If none exists, workspace admins can select **Create Brand Profile** in the header; members must ask an admin. **Add account** becomes available once a profile exists.

1. Select **Add account**.
2. Choose the owning Brand Profile.
3. Find the platform in the Social Channels list, using its search field if needed.
4. Select **Connect**, sign in on the platform, and approve the requested access.
5. Return to Channels and review the result. The account appears only after the connection is saved.

For another account on the same platform and profile, use **Add Another** in the connection dialog. A direct link to `/channels?tab=add` opens that dialog.

On phones, each platform's saved accounts and connection action appear below its identity instead of competing for the same row. Scroll the connection dialog to reach every platform; it stays within the available screen height, including landscape orientation.

Connection availability comes from the server and the platform's requirements. An unavailable provider is not a working connection action. Existing accounts remain identifiable by their saved name or provider account ID.

### Facebook Page selection

Facebook authorization opens **Select Facebook Page**. Choose one eligible Page and select **Connect Page**. Even a single eligible Page requires explicit confirmation; closing, cancelling, or pressing Escape does not add an account.

The selection expires after ten minutes. If it expires, start Connect again. For a connection-limit error, review [Resource limits](/docs/resource-limits), free capacity where appropriate, and retry while the selection is still valid. Meltiply does not provide a billing or upgrade flow.

Eligible Pages require the necessary content-creation access and publishing permissions. Token revocation or a change in platform permissions can invalidate a previously working connection.

### Supported providers

The connection flow currently includes TikTok, YouTube, Instagram, Facebook Pages, and Threads. Supported publishing formats and account requirements are shown by the real platform capabilities and composer validation; a listed provider does not imply every feature of its native app. Instagram and Threads also report stored performance metrics to the [Analytics](/docs/analytics) page when their engagement capabilities are accepted by the deployment.

## Use the Accounts directory

Each account row shows:

| Column        | What it contains                                                                                                            |
| ------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Account       | Avatar or initials, saved name, and available username/provider ID with copy controls.                                      |
| Platform      | The provider's mark and name.                                                                                               |
| Brand Profile | The owning profile, or Unknown profile when it no longer resolves.                                                          |
| Connection    | One health icon. Its accessible name and tooltip expose the status; connections needing attention provide recovery actions. |
| Settings      | The account's settings action, including permissions, publishing support, owning profile, and disconnect controls.          |

### Search and filters

Use account search to match account, platform, or profile names. The **Connection status** segments narrow the current health state.

Open **Filter** to add **Platform** or **Brand Profile** rows. Choose a field with its Add filter chip, then select a value. Adding an empty row does not change results. Supported rows combine with **and**.

- A row's trash control removes that filter.
- **Clear all** resets the builder.
- Active-value chips remove individual applied filters.
- **Clear filters** recovers a filtered-empty directory.

Selecting a Brand Profile scopes the shared Posts/Channels view. **All Brand Profiles** returns to aggregate review. Profiles are not sidebar sections; the top-bar jump search can also find a loaded profile.

### Select accounts

Select individual rows or use the header checkbox for all visible filtered accounts. The header is checked only when the entire visible set is selected; a partial selection leaves it visually unchecked.

The floating selection pill reports the actual count and offers **Disconnect** and the icon-only **Deselect** control. Disconnect confirms a fixed batch: successful accounts leave the selection, failed accounts remain selected for retry. Filtering does not discard hidden selections; changing Workspace or Brand Profile clears selection.

## Recover a connection

| Status             | Meaning                                   |
| ------------------ | ----------------------------------------- |
| Connected          | Authorization is working.                 |
| Expiring           | Authorization is nearing expiry.          |
| Expired            | Authorization must be renewed.            |
| Reconnect required | Authorize access again before publishing. |
| Revoked            | Access was withdrawn.                     |

For a connection needing attention:

1. Select its warning health icon and review the reason.
2. Choose **Re-authenticate** and approve access on the platform.
3. For Facebook, choose the same Page and confirm **Connect Page**.
4. Review the saved status when you return.

Re-authentication keeps the account's owning Brand Profile. An unrecognized connection-result code is not displayed as a success.

## Disconnect accounts

Open an account's **Channel settings**, choose **Disconnect**, and confirm. This works in aggregate and profile-filtered views; selected batches use the same confirmation principle.

Disconnecting removes the connection and stops scheduled/queued publishing for that account. It does not remove already-published platform copies. To revoke provider-side access, use that platform's app settings. To connect again later, start **Add account**.

## Manage Brand Profiles

The **Brand Profiles** tab shows actual profiles and their connected-account counts. These counts describe the workspace's connections, not just the current account filters. **View channels** applies the profile and returns to Accounts.

Admins can create a profile from the header or edit one from its card in the **Brand Profiles** tab. Creating a profile selects it and opens account connection. Deletion is in the profile editor and requires confirmation; read its consequences before proceeding.

See [Workspaces & Brand Profiles](/docs/workspaces) for ownership, permissions, and deletion behavior.
