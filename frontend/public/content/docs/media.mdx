Media belongs to a Post composition. There is no standalone Media Library route: use **Posts → Create post** or edit an eligible Post, then manage its attachments in the composer.

## Add attachments

1. Choose the Post's owning Brand Profile. All Brand Profiles is aggregate review; uploads require one owner.
2. Select **Add Media** or drag images/videos into the attachment area.
3. Review each attachment's upload and processing state before publishing.
4. Select destination channels when scheduling or publishing. Draft saving does not require a selected destination.

The Attached Media grid preserves the ordered Post attachment list. Platform validation uses the actual selected channels and their capabilities, not a generic promise that every platform accepts every format.

## Read attachment state

| State      | Meaning                                                  |
| ---------- | -------------------------------------------------------- |
| Preparing  | The upload session is being created.                     |
| Uploading  | Bytes are transferring; progress is shown.               |
| Paused     | You paused the transfer.                                 |
| Offline    | Connectivity interrupted the transfer.                   |
| Processing | The server is verifying media and preparing previews.    |
| Ready      | The asset is ready for scheduling/publication.           |
| Failed     | Upload or processing failed; read the actionable reason. |
| Cancelled  | The transfer was stopped.                                |

## Manage attachments

Hover or focus an attachment to reach its available controls:

- **Reorder** moves it earlier/later in delivery order.
- **Replace** changes the file while preserving its position and per-channel assignments.
- **Pause / Resume** controls an in-flight upload.
- **Retry** retries a failed transfer using its local file.
- **Remove** takes it out of the composition; removing an in-flight upload cancels that transfer.

Previews and actions remain part of the composer, not a separate reusable asset browser. Saving a Post retains its ordered relationships so reopening it restores the same composition.

## Customize for a channel

Selected channels inherit the Post's attachment order by default. In a destination channel's tab, change its included attachments when that provider needs a different selection. **Use all post attachments** restores inheritance.

The composer validates channel-specific media types, counts, file limits, and other publishing requirements. Fix a blocked channel's selection, replace the file, or deselect that destination; one platform's rules do not change another channel's saved selection.

## Recovery and errors

With functional cookie consent, browser-local recovery can retain in-progress text, attachment references, and channel overrides for the active workspace/profile. Without optional storage, composition and server-backed draft saving still work, but browser recovery is not available after leaving.

Returning to an in-progress upload may require the original local file. A failed server processing result is not a ready attachment; read the error and retry or replace it as offered. See [Cookies and storage](/docs/cookies) for persistence and [Resource limits](/docs/resource-limits) for quotas.
