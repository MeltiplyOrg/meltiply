Open **Settings** from the sidebar or mobile navigation. It is a full workspace page, not a modal. The section rail and page share a background; all sections use the same bounded, left-aligned content column so forms do not stretch across wide screens. On phones, section choices become a horizontal row and the content scrolls independently.

## Appearance

Choose **Light**, **Dark**, or **System** from the compact theme cards. The selected card is marked; palette changes preserve the page and your work. **System** follows device color-scheme changes while Meltiply is open.

The shared palette uses warm light surfaces, stone navigation, compact controls, and indigo actions. Dark mode keeps the same geometry with warm charcoal layers and a periwinkle accent. The application, landing page, and documentation share these tokens.

A theme choice works for the current page without optional storage. Remembering it across visits requires [functional cookie consent](/docs/cookies). Without an explicit choice, appearance follows the device.

There is one implemented animation path, with no separate motion mode or switch. Settings does not offer custom accents, density, or additional layout modes.

## Language

Choose **English** or **Español**. The interface changes immediately; remembering the selection across visits requires functional consent. Public guides are separate content rather than a promise that every article is translated.

## Publishing

Workspace Admins can choose the timezone every new schedule interprets and every schedule date displays in. Leave **Use this device's timezone** on to follow the current browser, or choose a supported IANA timezone such as `America/New_York`. Changing this preference never moves an existing Schedule: assigned instants stay exactly as stored. Providers receive only the stored instant; the timezone is a Meltiply entry and display choice, not a Platform publishing constraint.

Signatures are reusable text appended to new Posts. Add up to ten templates, name each one, and choose exactly one default. A template may use `{brand_profile}`, `{platform}`, and `{channel}`; the composer resolves them against the actual destination and shows the result before saving. A saved or published Post keeps the signature it stored, so later template edits do not rewrite it. Signature text counts toward each Platform's caption limit.

Notification choices cover failed publications and connected Channels that need reconnecting. Both events are off until you enable them. **Email** is offered only when this installation has working mail delivery; it sends to the Installation Owner's current address. Enabled alerts run through the durable queue with bounded retries, and a redelivery does not send the same event twice.

## Account

Review your name, email, and workspace as read-only identity details. **Sign out** is available here on desktop and phones, as well as in **Account menu → Sign out** at the bottom of the desktop sidebar or mobile navigation panel. The same menu opens Account settings and offers **Light / Dark / System** theme controls directly; changes apply immediately without leaving the menu.

The workspace name is not a workspace switcher. There is no plan-tier selector. Where an account avatar exists it is shown; missing/failed images use the shared user-icon fallback, not an email-derived avatar service.

## Security

Open Security to see password verification, authenticator controls, and the new-password form directly on the page. There is no additional opener hiding these options.

- **Verify your current password** for sensitive changes.
- **Change your password** using the current form and its validation.
- **Enable an authenticator** by completing setup and verifying a live code before activation.
- **Save recovery codes** offline. Each code is single-use; replacing the set invalidates the old codes.
- **Disable the authenticator** only through the password-verified action.

Keep passwords, setup keys, and recovery codes private. Follow each action's confirmation and session-handling instructions; opening a section is not sufficient authorization for a security change.

While a security request is running, or setup/recovery codes still need completion, section changes, navigation, and browser history keep you in Security. Finish verification, acknowledge saved recovery codes, or use **Cancel enrollment** before leaving. Reloading or closing the document warns that the current action will be interrupted. Passwords and setup details are cleared after an allowed departure.

## Profiles and connected accounts

Manage Brand Profiles and platform connections in [Channels](/docs/channels), not a generic Settings panel. The Brand Profiles tab shows real profile cards. Admins can create/edit profiles and confirm deletion; account settings expose permissions, publishing support, and disconnect controls.

Select a profile through Posts/Channels filters or top-bar jump search. **All Brand Profiles** restores aggregate review. A profile is an owning scope, not another workspace.

## What Settings does not include

The current route does not provide billing, API-key management, or self-service identity editing. Membership invitations, roles, installation lifecycle, and Audit live in **Administration**; owner notification choices live in **Publishing** and cover only publication-failure and disconnected-Channel alerts. Reference-design examples do not create those product capabilities.
